# Shader qualification — 2026-11-16

Six improvements are integrated into the existing built-in shaders; the shader
count, default selection and version are unchanged. Original source bytes are
retained in `examples/shader-baselines/`, with named A/B variants in
`examples/shader-candidates/`.

| Shader | Integrated behavior | AMD original → final ms/frame (median) |
| --- | --- | --- |
| Matrix | Resolution-aware glyph size, including small and portrait displays | 0.1218 → 0.1148 |
| Attitude | Aspect-correct instrument, compound flight motion, differentiated sky/ground | 0.3107 → 0.3192 |
| Circuit | Skip absent/out-of-footprint edges before palette work; defined smoothstep and zoom grid scale | 0.7676 → 0.4016 |
| Fibonacci | Retain rainbow seed field; remove the solid spiral overlay | 0.8149 → 0.7880 |
| Stonks | Bounded multiscale price process with continuous candles and derived decorative momentum | 0.0609 → 0.1371 |
| Mobius | More visible ribbon through lower camera elevation, steeper dip and bounded view roll; half-angle distance evaluation | 0.3069 → 0.2167 |

## Method and limits

The AMD runs used a Radeon RX 6700 XT, radeonsi/navi22/ACO, DRM 3.64,
Mesa 26.2.4 and OpenGL ES 3.2, through surfaceless EGL. No display/security
settings changed. Five alternating-order benchmark repetitions used 240 frames,
24 warmups, a 60-second animation span, 1920×1080, rainbow and one monitor.
Times are synchronized wall-clock rendering throughput (`glFinish`), not GPU
timer samples or utilization. Median/MAD and source hashes are in the companion
[qualification data](shader-qa-2026-11-16.json).

The regression warning threshold is the maximum of 15% of baseline time,
three times the sum of both MADs, and 0.1 ms/frame. This is a review aid, not a
claim of equivalent cost: **Stonks increases 125%, or 0.0762 ms/frame**, below
that absolute floor. Its final total is about 0.41% of a single-monitor 30 fps
frame budget. It is accepted for its changed visual behavior with that measured
cost explicitly retained. Mobius is about 29.4% faster than the original and
30% faster than its initially slower visual candidate. Smaller timing differences
for Matrix/Attitude/Fibonacci should not be treated as significant speedups.

AMD image validation covered 40 cases / 160 lossless PNG frames at times
0, 10, 20 and 30 seconds. All six used 800×480 and rainbow/forest; Matrix,
Attitude and Mobius also used 480×800. Eight shader-specific contracts passed:
Circuit stayed within one channel level, Fibonacci removed the overlay without
adding bright structures, and Mobius improved minimum visible coverage by at
least five percentage points. Contact sheets were reviewed. The Mobius
half-angle optimization was additionally compared with the same camera's
trigonometric version: maximum channel difference two, with fewer than
0.0024% of pixels differing by more than one level in the worst capture.

Earlier llvmpipe testing covered all seven original/candidate pairs at four
sizes and two palettes: 112 cases / 448 PNG frames, three timing repetitions
with 36 frames each. Smoke checks passed, but Stonks and Mobius had performance
warnings and Wormhole failed visual review. A subsequent polynomial hash reduced
Stonks software time by about 35–37% against that first candidate. Those earlier
results are historical evidence, not measurements of every final integrated
shader. Raw captures, logs and prior bytes remain in the task evidence directory.

After integration, all 153 Rust tests, all-target/all-feature Clippy, rustfmt
and both Python measurement/contract tests passed. The rebuilt six built-ins
matched the qualified variants byte-for-byte in all 24 paired PNG frames
(320×180, four timestamps, rainbow) on AMD. A focused Circuit run also verified
the preserved-baseline harness mode, including three repeated benchmarks and
image contracts, with no failures or warnings. Configuration was isolated.

## Wormhole remains open

The original built-in is retained. The first candidate produced flat fog patches.
Diagnosis against a fine-step first-crossing reference found exhausted raymarches
near tangencies. After that diagnosis, two materially new approaches were tried:
96-step bracket/refinement marching, then bounded analytic-slope/Newton stepping
with bracket refinement. Across four 160×90 phases, the second still missed
31 of 57,600 known intersections and chose five first-hit depths incorrectly by
more than 0.2 units. It is rejected despite its lower miss count. Numerical
contracts failed before GPU visual qualification.

The repository's two-attempt rule ends this round. Further work needs a new
first-root bracketing diagnosis, not another step-count adjustment. No rejected
Wormhole code is integrated. The retained example is explicitly marked rejected.

## Reproduction and acceptance still needed

See [the A/B example instructions](../examples/shader-candidates/README.md).
`render-preview` now supports `--start-time`, `--time-step` and `--frames-dir`.
`bench` returns failure for shader compile errors and writes escaped error JSON;
its percentage column now says frame budget rather than GPU utilization.

Offscreen AMD rendering is verified. Hyprland presentation, real multi-monitor
DPI/input dismissal and long-running physical display acceptance remain separate
manual checks. Other GPU/driver families remain unverified. No release, tag,
gallery deployment or hosted CI run is part of this qualification.
